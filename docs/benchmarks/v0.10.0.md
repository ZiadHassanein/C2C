# C2C v0.10.0: preserved evidence, smaller worker inputs

The efficiency change removes redundant transport metadata and repeated references to the same canonical context file. It preserves distinct files even when their text matches, all selected task evidence, participant roles/model IDs, report contents, security checks and review stages.

These measurements compare the model-routing implementation immediately before the efficiency change with the final v0.10.0 runtime. They use **24 complete offline workflows**, **78 captured prompts**, and **zero provider calls**. Fixed fictional reports permit exact content checks; they do not evaluate a real model's judgment.

## Ordinary inputs

With no repeated context paths, only redundant bookkeeping is removed. Token counts below use pinned tiktoken 0.12.0 and the o200k_base proxy encoding.

The newly selected background author adds real calls relative to a host-author route; this table does **not** claim that adding those calls reduces total planning usage.

## Deliberately repeated paths

The duplicate fixtures pass the first context file three times, including a path alias. Canonical-path deduplication keeps the first occurrence and every distinct file. The totals below include metadata removal; they must not be added to the ordinary-input percentages.

| Matching workflow | Successful worker calls | Before tokens | After tokens | Reduction |
|---|---:|---:|---:|---:|
| Host author · small review | 2 → 2 | 4,301 | 3,685 | **14.32%** |
| Background author · small review | 3 → 3 | 5,837 | 4,901 | **16.04%** |
| Host author · roadmap | 3 → 3 | 9,386 | 8,240 | **12.21%** |
| Background author · roadmap | 5 → 5 | 14,572 | 12,642 | **13.24%** |

These are controlled duplicate-input cases, not expected savings for normal projects. Separate fixtures with identical text in distinct files confirm that both source identities remain present.

## What was checked

- Exact task packets match after accounting only for removed run/derived-identity metadata and repeated canonical context entries.
- Actual participant providers, roles and model IDs remain; model identity caveats remain in the instructions and full metadata stays local.
- Independent proposals cannot see one another, and independent critiques cannot see the other critique.
- Security review, all findings/dispositions, unresolved roadmap policy questions and required call counts remain unchanged.
- Final-plan and decision-file hashes match for each baseline/candidate pair. Every context argument still receives the existing validation and secret scan; byte and file-count bounds remain enforced.

## Limits

Counts exclude the coordinator's research/chat, provider-added system/tool/schema envelopes, generated output and reasoning tokens. The test measures neither live latency, billed savings, cache hits, implementation correctness nor universal equal planning quality. Fresh model research and extra selected-worker calls can increase total usage. The efficiency change preserves the evidence and workflow requirements; it does not reduce models, effort, security or review depth to obtain smaller numbers.
